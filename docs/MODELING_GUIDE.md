# 모델링 규약 — 유입/유출부(포트)를 어떻게 만들 것인가

> 8번 질문에 대한 답입니다. **결론부터: 3ds Max 에서 아주 작은 박스를 만들어
> `PORT_IN@X-` / `PORT_OUT@X+` 같은 이름을 붙여 같이 내보내세요.**
> 그 외의 방법(더미 헬퍼, glTF extras)도 지원하지만 위 방법이 가장 안전합니다.

---

## 0. 왜 포트가 필요한가

컨베이어가 설비에 "확실하게" 물리려면 에디터가 세 가지를 알아야 합니다.

| 알아야 할 것 | 없으면 생기는 일 |
|---|---|
| **어디에** 붙는가 (X, Z) | 설비가 조금만 비대칭이면 엉뚱한 옆구리에 붙는다 |
| **어느 방향으로** 나가는가 | 벨트가 설비를 뚫고 지나가거나 비스듬히 튀어나온다 |
| **얼마나 높이** 붙는가 (Y) | 벨트면과 설비 반출구 높이가 안 맞아 자재가 공중에 뜬다 |

바운딩 박스만 보고 추측하면 이 세 가지를 다 틀립니다. 특히 높이는 절대 알 수 없습니다.
(포트가 없는 모델은 지금도 배치되지만, 에디터가 **bbox 네 변 중앙 · 높이 45%** 로
임의 생성한 포트를 씁니다. 인스펙터에 "자동 생성된 포트입니다" 라고 뜹니다.)

## 1. 권장 방식 — 마커 박스 (Marker Box)

### 만드는 법 (3ds Max 기준)

1. `Box` 를 하나 만듭니다. 크기는 **50 × 50 × 50 mm** 정도. 아주 작으면 됩니다.
2. 그 박스를 **자재가 실제로 드나드는 지점**에 놓습니다.
   - 평면 위치: 반출구/반입구의 중심
   - **높이(Z in Max / Y in glTF): 자재가 지나가는 면의 높이**
     ← 이 값이 그대로 컨베이어 벨트면 높이가 됩니다. 제일 중요합니다.
3. 이름을 규약대로 바꿉니다.
   ```
   PORT_IN@X-      ← 유입부, 설비의 -X 쪽으로 열려 있음
   PORT_OUT@X+     ← 유출부, 설비의 +X 쪽으로 열려 있음
   ```
4. 설비 본체와 **함께** GLB 로 내보냅니다. (Babylon glTF Exporter 그대로)

에디터가 로드할 때 이름이 `PORT_` 로 시작하는 노드는 **자동으로 숨깁니다.**
화면에는 안 보이고, 바운딩 박스(= 점유 면적) 계산에서도 빠집니다.
즉 마커 박스가 커도 설비가 커 보이지 않습니다.

### 왜 더미(Dummy) 헬퍼가 아니라 박스인가

더미 헬퍼도 지원합니다. 다만 익스포터/버전에 따라 **자식이 없는 헬퍼는 노드가
통째로 빠지는 경우**가 있습니다. 메시는 절대 누락되지 않습니다.
"확실하게" 가 중요하다고 하셨으니, 확실한 쪽을 기본으로 권합니다.

### 방향 접미사 `@X+` 를 쓰는 이유

방향은 세 단계로 판정합니다. 위에 있을수록 우선합니다.

| 순위 | 방법 | 비고 |
|---|---|---|
| 1 | **이름 접미사** `@X+` `@X-` `@Z+` `@Z-` | 익스포터가 회전을 어떻게 굽든 의도가 그대로 살아남음. **권장** |
| 2 | 노드 회전의 **로컬 +X 축** | 마커를 돌려서 방향을 준 경우 |
| 3 | bbox 중심 → 포트 방향의 지배축 | 회전도 접미사도 없을 때의 최후 수단 |

CAD 익스포트는 좌표계 변환(Z-up → Y-up)이 껴 있어서 회전이 의도대로 안 실리는
일이 흔합니다. 접미사는 그런 사고가 원천적으로 없습니다.

> ### ⚠ 이름과 마커 위치가 어긋나면 위치를 따릅니다
>
> `@X-` 라고 적었는데 마커가 **+Z 면**에 놓여 있는 식으로 둘이 직각으로 어긋나면,
> 에디터는 **마커 위치를 믿고 방향을 보정**합니다. 위치는 형상에서 직접 읽은
> 값이고 이름은 손으로 적은 값이라, 어긋났을 때 틀렸을 가능성이 높은 쪽은 이름이기
> 때문입니다. (보정 조건: 이름이 가리키는 축보다 다른 축 쪽으로 3배 이상,
> 그리고 0.25m 이상 치우쳐 있을 때)
>
> 보정이 일어나면 인스펙터의 포트 목록에 노란 경고가 뜹니다.
> **경고가 보이면 이름을 실제 방향에 맞게 고쳐서 다시 내보내세요.**
> 보정은 임시방편이고, 이름이 정확하면 추측할 일 자체가 없어집니다.
>
> 실제 예 — `Machine_1.glb` 의 두 포트는 이름이 `@X-` / `@X+` 인데 마커는
> ±Z 면에 있어 `Z+` / `Z−` 로 보정됩니다. 올바른 이름은
> `PORT_IN@Z+` / `PORT_OUT@Z-` 입니다.

## 2. 이름 규약 전체

```
PORT_IN                무방향 유입부  (방향은 2·3순위 규칙으로 추정)
PORT_OUT               무방향 유출부
PORT_IN@Z-             방향 명시
PORT_OUT_2@X+          같은 종류가 여러 개일 때 번호를 붙여도 됨
IN_MAIN@X-             PORT_ 대신 IN_ / OUT_ 로 시작해도 인식
```

- 대소문자 무시. `IN`/`OUT` 뒤에는 글자만 아니면 무엇이 와도 됩니다
  (`PORT_IN@Z+` 처럼 방향 접미사가 바로 붙는 형태가 표준입니다).
- `IN` / `OUT` 이 이름에 없으면 **양방향(any)** 포트로 취급되어 유입·유출 어느
  쪽으로든 연결됩니다. 급하면 그냥 `PORT_A@X+` 처럼 써도 동작합니다.

> **IN / OUT 을 제대로 적어야 하는 이유**
> 에디터는 **유입부끼리(IN↔IN) · 유출부끼리(OUT↔OUT) 연결을 막습니다.**
> 자재는 유출부 → 유입부로만 흐르기 때문입니다. 종류를 안 적어 `any` 가 되면
> 이 검사가 통과돼 버려서, 거꾸로 물린 라인을 잡아 주지 못합니다.
- glTF `extras` 에 `{"port": "in"}` 을 넣어도 인식합니다.
  (3ds Max 의 User Defined Properties → 익스포터가 extras 로 내보내는 경우)

## 3. 연결장치(컨베이어·레일) 모델 만들기

연결장치는 **"한 토막(1 피치)"** 만 만듭니다. 길이는 에디터가 늘립니다.

### 규칙

1. **길이축은 X** 로 두세요. (Z 로 만들어도 자동 판정하지만 X 가 표준)
2. 토막의 **유입·유출 포트를 반드시 넣으세요.**
   ```
   PORT_IN@X-     토막의 왼쪽 끝, 벨트면 높이
   PORT_OUT@X+    토막의 오른쪽 끝, 벨트면 높이
   ```
3. 두 포트 사이의 거리가 곧 **1 피치**가 됩니다.
   → 이게 중요한 이유: 프레임이 앞뒤로 조금 튀어나온 모델이라도, 피치는 포트
     기준으로 정확히 지켜지고 **튀어나온 여유살은 옆 토막과 자연스럽게 겹쳐서
     맞물립니다.** 포트 없이 bbox 로 재면 여유살까지 피치에 포함돼 마디마다
     틈이 벌어집니다.
4. 포트의 **높이(Y)가 벨트면**입니다. 설비 포트 높이와 이 값이 맞춰집니다.

### 길이는 어떻게 늘어나는가

```
타일 개수 = round(경로 길이 / 1 피치)
각 타일 배율 = 경로 길이 / (타일 개수 × 1 피치)     ← 보통 0.9 ~ 1.1
```

정수 개로 채우고 남는 오차만 미세하게 늘리거나 줄여 **틈 0** 으로 맞춥니다.
인스펙터에 `4 개 × 1.06 배` 처럼 표시됩니다.

### 커브는 어떻게 되는가

타일을 늘어놓기만 하면 코너에서 각집니다. 그래서 에디터는 **원본 메시를
길이축 방향으로 잘게 썰어(정점을 늘려) 경로를 따라 휩니다.**
분할 수는 코너 반경에 맞춰 자동으로 정해집니다(인스펙터 `곡선 분할` 항목).

여기서 나오는 실무 조언 하나:

> **길이 방향으로 긴 삼각형이 적을수록 곡선이 예쁘게 나옵니다.**
> 5m 옆판이 삼각형 2개로 되어 있으면 에디터가 그걸 40조각으로 썰어야 합니다.
> 모델링 단계에서 길이 방향으로 몇 번 나눠 두면(예: 0.5m 마다 엣지 하나)
> 썰기 비용이 줄고 셰이딩도 안정적입니다.

무거운 모델 보호를 위해 **삼각형 예산 40,000** 을 넘지 않는 선에서 분할 수를
자동으로 낮춥니다. 즉 5만 폴리짜리 컨베이어를 넣어도 죽지는 않지만, 곡선이
각져 보인다면 그건 원본이 무거워서입니다.

### 흐름축을 못 가리는 경우 (중요)

길이축은 다음 순서로 판정합니다.

| 순위 | 방법 |
|---|---|
| 1 | 라이브러리 항목 / 임포트 창에서 **직접 지정** |
| 2 | IN·OUT 포트가 벌어진 방향 |
| 3 | **벨트 윗면 UV 가 흐르도록 펴진 축** |
| 4 | bbox 가 긴 쪽 |

`Conveyor.glb` 처럼 **1 피치 1.000m · 폭 1.012m** 인 모델은 4번(bbox)으로는
절대 못 가립니다 — 오히려 폭이 더 길어서 반대로 판정됩니다.
이 모델이 제대로 동작하는 건 3번, 즉 벨트 UV 덕분입니다.

→ **컨베이어에는 되도록 `PORT_IN` / `PORT_OUT` 을 넣어 주세요.** 그러면 2번에서
확정되고, 덤으로 벨트면 높이와 정확한 피치까지 한 번에 해결됩니다.
그게 어렵다면 임포트 창에서 **흐름축을 직접 지정**하면 됩니다.

### 벨트를 별도 메시로 분리하기 (UV 애니메이션)

벨트를 별도 메시로 두고 **이름에 `Belt` 를 넣으면** 세 가지가 자동으로 됩니다.

1. **반송면 높이** — 벨트 메시의 윗면이 곧 자재가 실리는 높이가 됩니다.
   프레임 사이드레일이 벨트보다 높이 솟아 있어서, 이걸 구분하지 않으면
   벨트가 설비 포트보다 한참 아래로 가라앉습니다.
   (`Conveyor.glb` 기준 프레임 꼭대기 0.322m vs 벨트 윗면 0.142m — 18cm 차이)
2. **흐름축 판정** — 위의 3번 규칙.
3. **UV 구동** — 벨트 표면이 흐릅니다.

#### UV 는 "루프를 한 바퀴 감아" 펴세요

`Conveyor.glb` 의 벨트 UV 가 정확히 그렇게 되어 있습니다. U 좌표가
`아랫면 → 앞쪽 끝 → 윗면 → 뒤쪽 끝` 순으로 이어지며 한 바퀴 돌아갑니다.

```
윗면 :  U 0.789 → 2.034   (진행 방향으로 증가)
아랫면:  U 0.665 → -0.580  (진행 방향으로 감소)
```

이렇게 펴 두면 **U 오프셋 하나만 흘려도 윗면과 아랫면이 저절로 서로 반대로
움직입니다.** 실제 벨트가 도는 모습 그대로이고, UV 채널을 두 개 쓸 필요가
없습니다. 에디터는 이 방식으로 구동합니다.

> 요청하신 "두 채널이 서로 반대 방향" 은 지금 모델에서 **한 채널로 이미
> 충족**됩니다. 현재 `Conveyor.glb` 에는 `TEXCOORD_0` 하나만 들어 있고,
> 그것이 루프 전체를 감고 있어서 윗면·아랫면이 반대로 흐릅니다.
> 만약 "표면 무늬"와 "정지된 음영" 처럼 **서로 독립적인 두 레이어**를 겹치고
> 싶은 거라면 그건 UV 채널이 아니라 텍스처 슬롯이 두 개 필요한 이야기입니다.
> 그 경우 알려 주시면 셰이더를 그렇게 짜겠습니다.

에디터는 벨트 윗면의 UV 기울기(`흐름축 1m 당 U 변화량`, 이 모델은 **-1.245**)를
직접 재서 **m/s 단위 속도**로 환산합니다. 그래서 모델의 UV 스케일이 바뀌어도
"0.6 m/s" 라는 지정이 그대로 유효합니다.

체크리스트:
- [ ] 벨트가 프레임과 **별도 메시**이고 이름에 `Belt` 가 들어가는가
- [ ] 벨트 UV 가 루프를 감아 펴져 있는가 (윗면/아랫면 U 방향이 반대)
- [ ] U 가 흐르는 방향 = 자재가 가는 방향인가
- [ ] 텍스처 wrap 이 Repeat 인가 (glTF 기본값이라 보통 문제 없음)

## 3-1. 반송물(자재) 모델

`public/models/OBJ.glb` 하나가 **컨베이어 위를 흐르는 자재**로 쓰입니다.
라이브러리에 뜨지 않습니다 — 사용자가 놓는 물건이 아니라 설비가 내보내는
것이기 때문입니다.

- 원점은 **바닥면 중앙**(Y 최솟값 0). 그래야 벨트면 위에 정확히 얹힙니다.
- 진행 방향은 **+Z** 기준으로 회전시킵니다.
- **한 개만** 만드세요. 층수는 이 모델의 높이(0.294m)만큼 올려 가며 복제합니다.
- 벨트 폭보다 작아야 합니다. (`Conveyor.glb` 벨트 폭 0.8m ↔ 자재 0.69 × 0.68m)

교체하려면 같은 경로에 덮어쓰면 됩니다. 크기·높이는 자동으로 다시 잽니다.

## 3-2. 카트 모델 만들기

카트는 **본체 + 적재물** 두 메시로 나눕니다.

```
Cart          본체. 원점은 바닥면 중앙, 진행 방향이 긴 축(Z 권장)
OBJ           싣고 다니는 물건. 1개 분량만 만들어 데크 위에 올려 둡니다
```

- 적재물 노드 이름은 `OBJ` (또는 `payload` / `적재물` / `load` 로 시작).
- **1단만 만드세요.** 여러 개를 실을 때는 에디터가 이 노드를 자기 높이만큼
  올려 가며 복제해 쌓습니다. 그래서 **적재물의 높이가 곧 한 단의 간격**입니다.
  (`Cart.glb` 기준 0.294m)
- 적재물은 처음부터 **데크 위 제자리**에 놓아 두세요. 1단은 모델에 구워진
  그 위치 그대로 나오고, 2단부터 그 위로 쌓입니다.
- 평소에는 보이지 않다가 설비 유출부를 지날 때 나타나고 유입부에서 사라집니다.
  모델에서 숨겨 둘 필요는 없습니다.

몇 개를 싣는지는 모델이 아니라 **설비마다** 정합니다 — 설비를 선택하면
인스펙터에 "한 번에 내보내는 수량" 이 있습니다.

### 전선·배관처럼 형상이 단순한 것

모델을 만들지 말고 라이브러리에서 **연장 방식 = 튜브** 를 고르세요.
반지름과 처짐(sag)만으로 절차적으로 생성되며 곡선이 완벽하게 매끄럽습니다.
기본 제공되는 `전선 (케이블)` · `배관 (파이프)` 이 그 예입니다.

## 4. 설비 모델 공통 규칙

| 항목 | 규칙 |
|---|---|
| 단위 | **미터** |
| 업축 | Y-up (Babylon 익스포터가 알아서 변환) |
| 원점 | **바닥면 중앙**. 즉 모델의 Y 최솟값이 0 |
| 회전 | 0° 상태에서 정면이 **+X** 를 보도록 (배치 시 90° 단위로 회전) |
| 포맷 | glTF 2.0 binary (`.glb`) |

원점이 바닥면에 있어야 그리드(Y=0) 위에 그대로 앉습니다. 원점이 물체 중앙에
있으면 절반이 바닥에 묻힙니다.

점유 면적(풋프린트)은 포트 마커를 뺀 실제 형상의 XZ 바운딩 박스입니다.
울타리처럼 넓게 잡아 두면 그만큼 자리를 차지하니, 안전 펜스를 포함할지
말지는 의도적으로 결정하세요.

---

## 5. 체크리스트 (내보내기 전)

- [ ] 단위 미터, 크기가 실제 치수와 같은가
- [ ] 원점이 바닥면 중앙인가 (Y 최솟값 = 0)
- [ ] `PORT_IN@…` / `PORT_OUT@…` 마커가 **자재가 지나가는 높이**에 있는가
- [ ] 마커 이름에 방향 접미사(`@X+` 등)를 붙였는가
- [ ] 연결장치라면 두 포트 사이 거리 = 의도한 1 피치인가
- [ ] 연결장치라면 벨트가 별도 메시(`*Belt*`)이고 UV 가 루프를 감고 있는가
- [ ] 불필요한 히스토리·카메라·라이트를 빼고 내보냈는가

등록 직후 라이브러리 추가 창에서 **`포트 4개 (모델 정의)`** 라고 나오면 성공입니다.
`(자동 생성)` 이라고 나오면 마커가 인식되지 않은 것이니 이름을 확인하세요.

## 6. 규약이 코드 어디에 있는가

| 내용 | 파일 |
|---|---|
| 포트 추출 규칙(이름·방향·폴백·보정) | `src/core/ports.js` |
| 벨트 서브메시 분석(높이·축·UV 기울기) | `src/core/ports.js` → `analyzeBelt()` |
| 연결장치 1 피치·폭 계산 | `src/core/ports.js` → `analyzeConnector()` |
| 타일링 · 커브 디폼 · 메시 썰기 · 폭 배율 | `src/scene/connectorGeometry.js` |
| 벨트 UV 구동 | `src/scene/ConnectorView.jsx` |
| 경로 라우팅(직교 + 코너 필렛 + 층 램프) | `src/core/routing.js` |
| 겹침 판정 · 자동 층 배정 | `src/core/link.js` |
| 그리드 스냅 · 면 맞춤 · 충돌 | `src/core/grid.js` |

규약을 바꾸고 싶으면 `ports.js` 상단의 정규식 세 개(`PORT_NAME`, `DIR_SUFFIX`,
`KIND_IN`/`KIND_OUT`)만 손보면 됩니다.
