# EGIS Smart Factory — 설비 배치 에디터 · 라인 시뮬레이터

팩토리오/새티스팩토리 식으로 **설비를 직접 골라 배치하고, 설비끼리 컨베이어·레일·
전선으로 잇는** 스마트 팩토리 레이아웃 빌더입니다. 연결장치는 두 설비 사이 거리에
맞춰 **모델이 자동으로 연장되고, 코너에서는 곡선으로 휩니다.**

그리는 데서 끝나지 않습니다. 그린 도면을 **그대로 돌려 봅니다** — 설비마다 공정
시간과 레시피가 있고, 사람이 없으면 서고, 고장 나고, 불량이 납니다. 돌리고 나면
**어디가 병목이었고 얼마가 들었는지**를 지표·보고서·원가로 되돌려 줍니다.

```bash
npm install
npm run dev      # http://localhost:5174
npm test         # 868건, 의존성 없이 3초
```

## 처음이라면 — 따라 하기

툴바 12시 방향의 🎓 **따라 하기** 버튼을 누르면 **갈래를 고르는 창**이 먼저 뜹니다.
한 줄짜리 40걸음 대신, 궁금한 것만 골라서 밟습니다.

| 갈래 | 무엇을 | 걸음 |
|---|---|---|
| **처음부터** | 바닥·벽·설비·연결·실행 | 7 |
| **설비 다루기** | 공정 시간·한 번에 몇 개·불량·전력 | 4 |
| **쌓는 곳** | 선반·줄·적치대 | 3 |
| **실어 나르기** | 카트 경로·정차역·역할 | 3 |
| **사람** | 인원·교대 | 2 |
| **돈** | 단가·원가 구성·손실 | 3 |
| **계획** | 생산 오더·납기·라인 능력 | 3 |
| **나눠 쓰기** | 내보내기·올리기·공용 도면 | 3 |

각 걸음은 **도면 상태를 보고 스스로 체크**됩니다 — 「다음」을 눌러 넘기는 것이
아니라 실제로 그 일을 해야 넘어갑니다. 안내가 가리키는 칸은 화면에서 **테두리가
빛납니다.**

## 쓰는 법

### 설비 놓기
1. 좌측 **설비** 탭에서 항목을 클릭 → 자동으로 **탑뷰**로 전환됩니다.
2. 마우스를 움직이면 고스트가 그리드에 붙어 따라옵니다.
   - **파랑** = 놓을 수 있음 / **빨강** = 다른 설비와 겹치거나 도면 밖
3. `R` 로 90° 회전, 클릭해서 확정. 도구는 유지되므로 연속 배치가 됩니다.
4. 옆 설비 가까이 가져가면 **면끼리 딱 맞게** 달라붙습니다(툴바의 자석 아이콘).

### 연결하기
1. 좌측 **연결장치** 탭에서 항목을 클릭.
2. 설비마다 **포트 화살표**가 뜹니다. 초록=유입 · 주황=유출 · 하늘=양방향.
3. **출발 포트 → 도착 포트** 순서로 클릭하면 경로가 생성됩니다.
   - 커서가 포트 2m 안에 들어가면 자동으로 달라붙습니다.
   - 빈 바닥을 클릭하면 **자유 끝점**으로 끝납니다(아직 설비가 없는 자리).
4. 경로는 항상 축 정렬 직교 경로이고, 꺾이는 곳은 곡선이 됩니다.
   코너 반경은 인스펙터에서 연결마다 조절합니다.

**유입↔유입 · 유출↔유출은 이어지지 않습니다.** 자재는 유출부에서 유입부로만
흐르기 때문입니다. 출발 포트를 고르면 이을 수 없는 포트는 **회색으로 죽어서**
달라붙지도 않고, 그래도 눌렀다면 이유를 알려 주고 아무 일도 하지 않습니다.
종류가 지정되지 않은 포트(하늘색, 모델에 IN/OUT 정의가 없는 경우)는 양쪽 다 됩니다.

유입부에서 출발해 유출부로 그려도 됩니다 — 저장할 때 자동으로 뒤집어
**항상 "유출 → 유입"** 으로 남습니다. 그리는 순서까지 강요하지는 않습니다.

### 벨트 위를 흐르는 자재
설비의 **유출부**에서 나가는 컨베이어 위로 자재(`OBJ.glb`)가 흘러갑니다.
설비를 선택하면 **생산** 항목에서 정합니다.

| 설정 | 뜻 |
|---|---|
| **만드는 시간** | 한 개에 몇 초 (기본 6초/개). 이 값이 설비의 처리량을 정합니다 |
| **시간 편차** | ±% 로 흔듭니다. 0 이면 늘 같은 시간 — **편차를 줘야 버퍼가 왜 필요한지** 드러납니다 |
| **한 번에** | 한 묶음 몇 개씩 내보낼지 (1~8, 기본 3). 벨트 위에 그만큼 층으로 쌓이고, **카트도 같은 수로 싣습니다** |
| 간격 (자동) | 읽기 전용 |

**간격은 사람이 정하지 않습니다.** 예전에는 슬라이더였는데 맞출 방법이 없었습니다 —
촘촘히 할수록 좋은 게 아니라 톱니처럼 오르내려서, 4.0m 에서 3.5m 로 좁히면 처리량이
114 → 65 로 반토막 났습니다(벨트 칸이 빈 채로 먼저 지나가 다음 칸을 기다립니다).
설비가 한 덩어리 내는 박자에 맞추는 값 **하나만 정답**이라, 그건 도구가 계산합니다.

자재는 벨트 끝(다음 설비의 유입부)에 닿으면 그 설비의 **재고로 들어갑니다.**
툴바의 ▶/⏸ 로 벨트 구동과 함께 멈추고 움직입니다.

### 그린 뒤에 라인 고치기
연결장치를 선택하면 경로 위에 손잡이가 뜹니다.
**진한 점**은 경유점이라 끌어서 옮기고, **흐린 점**(구간 중점)을 끌면 그 자리에
경유점이 새로 생기면서 곧바로 끌려옵니다. **Alt+클릭**으로 지웁니다.
인스펙터에서 좌표를 확인하거나 "경유점 모두 지우고 자동 경로로" 되돌릴 수 있습니다.

### 배관 · 전선
자재가 흐르는 물건이 아니라 설비 부속이므로 **컨베이어 포트를 쓰지 않습니다.**
품목마다 정해진 높이(전선 4.0m 상부 · 배관 0.35m 바닥)에 놓이고, 인스펙터에서
연결마다 높이를 바꿀 수 있습니다. 클릭한 자리에 따라 세 가지로 붙습니다.

| 클릭한 곳 | 결과 |
|---|---|
| 같은 종류의 기존 배관 위 | **분기점(T·+)** — 그 배관을 따라 움직입니다 |
| 설비 위(또는 0.8m 이내) | 설비에 붙는 접점 — 설비를 옮기거나 돌리면 따라갑니다 |
| 그 외 빈 바닥 | 자유 끝점 |

배관·전선은 **겹쳐도 층을 쌓지 않습니다.** T·+ 자로 만나는 게 정상이기 때문입니다.
(층 쌓기는 컨베이어·레일에만 적용됩니다)

### 카트
1. 좌측 **카트** 탭에서 항목을 클릭.
2. 바닥을 눌러 **순찰 경로**를 찍습니다. **더블클릭**(또는 Enter)으로 마치고,
   **첫 점을 다시 누르면 고리**로 닫힙니다. Backspace 로 마지막 점을 물립니다.
3. 카트가 그 경로를 왕복합니다(고리면 계속 순환). 속도·코너 반경·정차 시간은
   인스펙터에서 조절합니다.
4. **배치 대수**로 한 경로에 여러 대를 올립니다(1~10대). 출발 지점을 경로 길이만큼
   고르게 나눠 서로 붙어 다니지 않습니다. 여러 대를 굴릴 거라면 **고리로 순환**을
   켜세요 — 왕복 경로에서는 되돌아오는 카트끼리 스쳐 지나갑니다.

**정차역은 따로 찍지 않습니다.** 경로가 설비 포트 **정면 1m 안**(`STATION_DIST`)을
지나가면 그 지점이 자동으로 역이 됩니다.

- **유출부** 앞을 지나면 → 그 설비의 "한 번에" 수량만큼 **층층이 싣고**
- **유입부** 앞을 지나면 → **내려놓습니다**

옆구리를 스쳐 지나가는 것은 역으로 치지 않습니다. 설비 하나의 유입·유출부는
앞뒤 면에 붙어 있어서, 거리만 보면 옆을 지날 때 둘 다 걸려 싣자마자 내리는
동작이 되기 때문입니다.

카트를 선택하면 **정차역 N개** 칸에 잡힌 역이 전부 나옵니다. 선반은 한 줄에 붙은
**싣기 / 내리기** 버튼으로 바꿉니다 — 경로를 그릴 때 **가까이 지나간 쪽으로 이미
정해져 있고**, 그 결과가 켜져 있습니다. 누르면 그때부터 못 박히고, 누르기 전에는
경로를 옮기면 다시 따라갑니다. 설비 포트와 적치대는 형상으로 정해져 바꿀 수 없습니다.

> **싣기만 있거나 내리기만 있으면 경고가 뜹니다.** 싣기만 있으면 내려놓을 데가
> 없어 실은 채로 영영 돌고, 내리기만 있으면 빈 차로 돕니다 — 둘 다 나르는 양이
> **0** 인데 화면으로는 「경로도 있고 역도 여럿」이라 멀쩡해 보이기 때문입니다.

> **싣는 곳이 둘인데 한 곳만 쓰이면 그것도 말해 줍니다.** 카트는 비어 있을 때만
> 싣기 때문에, 내려놓고 나서 **먼저 만나는 싣는 곳**에서 이미 차 버립니다 —
> 나머지는 짐을 진 채 지나칩니다. 화면으로는 「역이 넷이고 다 잡혔다」로 보이는데
> 한쪽 적치대만 비고 다른 쪽은 차서 그 위 벨트와 설비가 줄줄이 섭니다.
> 경로를 나눠 카트를 따로 두거나, 내리는 곳이 두 싣는 곳 **사이에** 오게 하세요.

### 선반 (랙)
**운송/적재** 탭에서 고르고 클릭해서 놓습니다. 설비와 같은 그리드·면 맞춤이 걸립니다.

형상이 모델이 아니라 **설정값**에서 나옵니다. 모델(`Shelf.glb`)은 판 한 장과 기둥으로
분해되어 필요한 만큼 다시 쌓입니다.

| 설정 | 범위 | 비고 |
|---|---|---|
| **칸 수** | 1~10칸 | 배치 중 <kbd>[</kbd> <kbd>]</kbd> 로도 조절 |
| **한 칸 길이** | 1.0~6.0 m | 기본값은 모델의 기둥 간격(2.59m) |
| **단 수** | 1~10단 | 기본 3단 |
| **단 간격** | 0.4~3.0 m | 기본값은 모델의 판 간격(1.4m) |
| **빈 카트에 실어 보낼 수량** | 0~12개 | 출고량 |

한 단 적재수는 길이에 맞춰 **자동**으로 정해집니다.
이어지는 자리에는 기둥이 하나만 남습니다(3칸이면 기둥 4개).
길이나 단 수를 **줄이면 넘치는 재고는 자동으로 잘립니다.**

#### 입고 · 출고 구역
선반 **앞뒤 양면** 바닥에 구역이 반씩 깔려 있습니다.

- 🟩 **녹색 = 내리기** — 자재를 싣고 있는 카트가 지나면 **내려놓습니다**
  (수용량을 넘으면 들어가는 만큼만, 나머지는 계속 싣고 감)
- 🟧 **주황 = 싣기** — 빈 카트가 지나면 설정한 수량만큼 **실어 갑니다**
  (재고가 모자라면 있는 만큼)

색 규칙은 설비에서도 같습니다 — **주황은 카트가 싣는 곳, 녹색은 내리는 곳**입니다.

자리를 갈라 둔 덕분에 "어디로 지나가느냐" 가 곧 "무엇을 할 것이냐" 가 됩니다.
여기에 같은 선반에서 넣었다 뺐다 하는 것을 막는 규칙 세 가지가 붙습니다.

1. **한 선반은 한 카트 경로에 대해 역할 하나만 갖습니다.**
   경로가 더 가까이 지나가는 쪽(녹색 또는 주황) 하나만 정차역이 됩니다.
   → 이 선반을 **싣는 곳**으로 쓰려면 경로를 **주황 절반 위로**,
   **내리는 곳**으로 쓰려면 **녹색 절반 위로** 그으세요.
2. **실어 온 곳에는 도로 내려놓지 않습니다.** 카트는 지금 실은 짐을 어디서
   받았는지 기억하고, 그 선반의 녹색 구역은 건너뜁니다.
3. **한 번 자재를 주고받은 역은 다른 곳을 거치기 전까지 다시 반응하지 않습니다.**
   (그냥 지나가기만 한 경우는 들른 것으로 치지 않습니다)

재고는 `OBJ` 모델로 아래 단부터 가로로 채워 올라가고, 인스펙터에서
**가득 채우기 / 비우기** 로 직접 맞출 수도 있습니다.
시뮬레이션 값이라 도면 파일에 저장되지 않습니다 — 새로고침하면 비워집니다.

### 바닥의 입출고 표시
카트 경로를 그릴 때 어디로 선을 그어야 할지 보이도록, 선택하지 않아도 **늘 바닥에**
녹색/주황 면이 깔립니다.

- **선반** — 앞뒤 양면에 입고(녹색)·출고(주황)
- **설비** — 유입부(녹색)·유출부(주황). 단, **컨베이어가 물려 있지 않은 포트만** 표시합니다.
  이미 벨트가 붙은 포트는 카트가 갈 일이 없기 때문입니다.

### 무엇을 만드는가 — 레시피 (`core/bom.js`)
설비를 선택해 **만드는 것** 칸에서 「무엇 몇 개를 먹어 무엇을 낸다」를 정합니다.
공정 순서는 **적지 않습니다** — 벨트가 어디로 물렸는지에서 읽습니다. 레시피가
쓰지 않는 종류는 벨트도 안 받고 카트도 안 내려놓습니다.

버퍼 자리는 **종류마다 나뉩니다.** 한 종류가 자리를 다 먹어 다른 종류가 영영 못
들어오는 교착을 규칙 자체로 없앤 것입니다.

### 왜 섰는가 — 서는 이유 다섯 가지
| 이유 | 뜻 | 어느 쪽으로 번지나 |
|---|---|---|
| **막힘**(blocked) | 만들어 놨는데 내보낼 데가 없다 | 뒤(상류)로 |
| **굶음**(starved) | 재료가 안 온다 | 앞(하류)로 |
| **무인**(unmanned) | 이 교대에 사람이 모자란다 | — |
| **고장**(down) | MTBF 로 서고 MTTR 만에 돌아온다 | — |
| **전환**(setup) | 로트를 바꾸는 중이다 | — |

빨갛게 선 설비를 누르면 **범인까지 거슬러 올라가 짚습니다**(`core/diagnose.js`).
「막혔다」는 결과지 원인이 아니기 때문입니다. 알람을 누르면 그 설비로 **화면이
날아갑니다**.

### 로트 전환 · 품종 전환 (`core/process.js`)
설비는 계속 같은 것만 뽑지 않습니다. 몇 개 만들고 나면 **날을 갈고, 금형을 바꾸고,
청소를 합니다.** 그동안은 아무것도 안 나옵니다.

설비를 고르고 **로트 크기**(몇 개마다)와 **전환 시간**(몇 초)을 정합니다.

    실질 공정 = 공정 + 전환/로트      6초 + 300초/20개 = 21초/개

**라인 능력(천장)이 이 값을 씁니다.** 안 그러면 「돌리기 전 계산」과 「돌려 본
결과」가 갈리고, 라인이 천장의 절반밖에 안 나오는데 이유를 화면 어디에서도
못 찾게 됩니다.

> **이름은 그 설비가 든 품종 수를 따라갑니다.** 품종이 하나면 바꿀 것이 없으니
> 「로트 전환」이고, 드는 것은 날 갈기·청소입니다. 품종이 여럿이면 그때 비로소
> 「품종 전환」이 되고, 화면의 이름도 그렇게 바뀝니다. 품종이 하나뿐인데 「품종
> 전환」이라 부르면 화면이 거짓말을 하는 것입니다.

#### 한 설비가 여러 품종을 만든다

「만드는 것」 칸 맨 위의 **칩**으로 품종을 더합니다. **칩의 차례가 곧 만드는
차례**이고, 로트를 채우면 다음 칩으로 넘어갑니다.

    1. 제작품 R   [2. 제작품 G]   + 품종            🗑
    20개를 만들면 다음 품종으로 넘어갑니다 — 한 품종을 기다리는 시간은 2배가 됩니다.

한 번에 **한 품종만** 보여 줍니다 — 재료·버퍼 자리·부족분이 모두 품종마다 달라서
한 판에 펼치면 어느 줄이 어디 것인지 못 읽습니다.

**천장이 품종 수만큼 나뉩니다.** 2초짜리 설비가 두 품종을 20개씩 번갈아 만들면
제작품 R 은 「2초에 하나」가 아니라 **한 품종에 7초/개**입니다. 화면이 그 셈을
그대로 적어 줍니다. 실제로 돌려 본 값(제작기 → 벨트 → 적치대, 300초):

    | 도면                | 천장(계산) | 실제      | 적치대에 쌓인 것        |
    |---------------------|-----------|----------|------------------------|
    | 품종 1 · 전환 없음   | 1800 개/시 | 1692 개/시 | 제작품 R 141           |
    | 품종 1 · 20개/30초   | 1029 개/시 |  972 개/시 | 제작품 R 81            |
    | 품종 2 · 20개/30초   |  514 개/시 |  468 개/시 | 제작품 R 40 · G 38     |

셋 다 천장의 91~94% 이고, 그 차이는 벨트를 채우는 시간입니다 — 세 경우에 고릅니다.
**계산과 실측이 만나는 것이 이 기능의 값입니다.**

종류는 **끝까지 따라갑니다.** 벨트는 칸마다 무엇이 실렸는지 들고 있고(줄 전체에
이름표 하나면 벨트가 길수록 어긋납니다), 적치대에는 로트 단위로 도착합니다:

    RRRRRRRRRRRRRRRRRRRRGGGGGGGGGGGGGGGGGGGGRRRRRRRRRR

> **로트 크기가 0이면 안 바뀝니다** — 첫 품종만 계속 만듭니다. 도면에는 둘이
> 적혀 있는데 라인에는 하나만 흐르는 상태라, 화면이 그 자리에서 짚어 줍니다.

> 한 설비에 품종은 **넷까지**(`MAX_KINDS`). 넘기면 전환에 드는 시간이 만드는
> 시간을 넘어서 라인이 사실상 서고, 칩 줄도 접혀 차례를 못 읽습니다.

전환 시간은 **가동률(A)** 에서 빠집니다 — 고장·무인과 같은 자리입니다.
푸는 방법이 **로트를 키우거나 빠르게 바꾸는 것**(SMED)이라 따로 셉니다.

> 짧게 돌리면 **천장보다 높게** 나올 수 있습니다 — 마지막 전환을 안 치르기
> 때문입니다(1800초 200개/시 → 18000초 172개/시 → 천장 171.4).

### 불량 · 재작업 (`core/faults.js` · `core/process.js`)
설비마다 **불량률**을 줍니다. 불량은 **만들 때** 판정합니다 — 걸러진 것은 벨트를
안 탑니다.

> 예전에는 벨트가 종점에 닿을 때 걸렀습니다. 그래서 **카트로 나르는 설비는 불량이
> 아예 안 나왔고**(거르는 자리가 벨트에만 있었습니다), 다 흘러간 뒤라 재작업으로
> 되돌릴 수도 없었습니다.

**재작업 시간**을 주면 버리는 대신 다시 만듭니다. 재작업품은 그 설비의 줄에 서고
다음에 그것부터 처리합니다 — **재료는 안 듭니다.** 이미 물건이 되어 있으니까요.

다시 만든 것도 **같은 불량률을 한 번 더** 지납니다. 두 번째 불량은 버립니다.
「고치면 무조건 살아난다」로 두면 불량률을 아무리 올려도 양품률이 100% 라 화면이
거짓말을 합니다.

**천장이 이것을 압니다.** 열 개 만들어 하나를 버리면 양품 한 개에 드는 시간이
늘어납니다:

    버릴 때        공정 ÷ (1 − 불량률)
    다시 만들 때   (공정 + 불량률 × 재작업) ÷ (1 − 불량률²)

제작기 6초/개 · 벨트 · 적치대, 예열 300초 뒤 900초, 씨앗 여섯 판 평균:

| 도면 | 천장(계산) | 양품 실제 | 화면이 적는 설명 |
|---|---|---|---|
| 불량 없음 | 600 개/시 | 600 개/시 | 공정 6초/개 |
| 불량 10% · 폐기 | 540 개/시 | 515 개/시 | 공정 6초 · 불량 10% 버림 = 양품 6.7초/개 |
| 불량 10% · 재작업 6초 | 540 개/시 | 529 개/시 | 공정 6초 · 불량 10% 재작업 6초 = 양품 6.7초/개 |
| 불량 10% · 재작업 30초 | 396 개/시 | 397 개/시 | 공정 6초 · 불량 10% 재작업 30초 = 양품 9.1초/개 |
| 불량 30% · 폐기 | 420 개/시 | 391 개/시 | 공정 6초 · 불량 30% 버림 = 양품 8.6초/개 |

**재작업 30초짜리는 천장이 396으로 내려앉습니다** — 같은 설비인데 능력이
3분의 2입니다. 재작업이 쌀 때는 버리는 것보다 낫고, 비싸지면 버리는 쪽이
낫습니다. 그 갈림이 돌리기 전에 나오는 것이 이 기능의 쓸모입니다.

설비를 고르면 **그 설비가** 버린 것과 다시 만든 것을 따로 보여 줍니다:

    · 양품률   91%   (19개 버림 · 12개 재작업)

**재작업은 양품률을 안 깎습니다** — 살아났으니까요. 대신 시간을 썼고, 두 값을
나란히 봐야 「불량을 재작업으로 덮고 있다」가 보입니다.

> **불량품이 다른 길로 흐르지는 않습니다.** 검사대를 따로 두고 불량만 다른
> 벨트로 빼내는 라우팅은 아직 없습니다 — 벨트 칸과 적치대가 「종류」로만 물건을
> 가르기 때문에, 같은 종류의 양·불을 가르려면 그 전체를 손대야 합니다.
> 지금 모델은 **고치는 자리가 만든 자리와 같습니다.**

### 배치 공정 (`core/process.js`)
오븐 · 도장 부스 · 열처리로 · 세척기. 이런 설비는 한 개씩 흘려보내지 않고
**한 판을 모아 한 번에** 처리합니다. 「한 판에」를 올리면 배치 설비가 됩니다.

    개당 = 공정 ÷ 판 크기        600초 ÷ 20개 = 30초/개

**공정 시간은 한 판에 드는 시간입니다.** 판이 20개든 1개든 굽는 시간은 같아서,
판이 클수록 개당이 싸집니다. 화면의 이름도 「만드는 시간 (한 판)」으로 바뀌고
단위가 초/개에서 **초/판**으로 바뀝니다.

**덜 찬 판은 어떻게 하나.** 「꽉 차야 굽는다」로 두면 앞 공정이 느릴 때 20개가
영영 안 모여 **라인이 통째로 섭니다.** 그래서 「덜 차면 기다리기」 한도를 둡니다.

| 한도 | 뜻 |
|---|---|
| **0 초** (기본) | 안 기다립니다 — **있는 만큼** 굽습니다 |
| **T 초** | 판이 차거나 T초가 지나면 굽습니다 |

0으로 두어도 배치는 제 노릇을 합니다. 오븐이 병목이면 굽는 동안 앞에 재료가
쌓여서 **다음 판은 저절로 꽉 찹니다** — 스스로 균형을 잡습니다. 한도를 주는 것은
재료가 띄엄띄엄 올 때 굽는 횟수를 줄이려는 선택입니다.

판을 채우며 기다리는 시간은 **굶음**으로 셉니다. 서 있는 이유를 가르는 잣대는 늘
같습니다 — 푸는 방법이 다른가. 판을 못 채워 기다리는 것은 앞 공정을 빠르게 하거나
판을 줄여서 풀고, 재료가 없어 서 있는 것과 처방이 같습니다.

정상 상태 처리량 (제작기 → 오븐 → 벨트 → 적치대, 예열 600초 뒤 1800초):

| 설비 | 천장(계산) | 실제 | 화면이 적는 설명 |
|---|---|---|---|
| 한 개씩 · 12초 | 300 개/시 | 298 개/시 | 공정 12초/개 |
| 한 판 5개 · 60초 | 300 개/시 | 300 개/시 | 공정 60초 · 한 판에 5개 = 12.0초/개 |
| 한 판 10개 · 120초 | 300 개/시 | 300 개/시 | 공정 120초 · 한 판에 10개 = 12.0초/개 |
| 한 판 20개 · 240초 | 300 개/시 | 280 개/시 | 공정 240초 · 한 판에 20개 = 12.0초/개 |

> **출력 자리는 판 두 개분 + 한 덩어리**로 잡힙니다. 한 판이 나가는 동안 다음
> 판을 구워야 하기 때문입니다 — 한 판치만 두면 다 굽고도 앞판이 빠질 때까지
> 서 있어서 60초 오븐이 120초에 한 판씩 냅니다.

### 흔들림의 모양 (`core/random.js`)
**시간 편차**를 주면 그 흔들림이 **어떤 모양**인지도 고릅니다.

| 고르기 | 통계 | 뜻 |
|---|---|---|
| **고르게** | 균등 | ± 안에서 아무 값이나 똑같이 — 같은 ± 면 **제일 크게 흔들립니다** |
| **가운데로** | 정규 | 가운데가 흔하고 양끝이 드뭅니다 |
| **가끔 길게** | 로그정규 | 대개 비슷한데 **드물게 몇 배로 늦습니다** — 공정·수리의 현실 |
| **최소·보통·최대** | 삼각 | 보통값이 제일 흔합니다 — 넷 중 가장 얌전합니다 |

> **넷 다 평균이 1 입니다.** 모양을 바꿔도 **라인의 천장은 안 움직입니다** —
> 달라지는 것은 흔들림뿐입니다. 안 그러면 두 배치를 견줄 때 배치 차이인지
> 분포 차이인지 알 수 없어집니다.

버퍼 8칸짜리 라인을 30분 × 20판 돌려 잰 값입니다.

    모양          평균 막힘  가장 나쁜 판  한 개 최대배수
    고르게          79초       96초        1.50배
    가운데로        58초       75초        2.03배
    가끔 길게       55초       71초        2.68배
    최소·보통·최대   45초       61초        1.50배

**막힘은 꼬리가 아니라 흔들림의 크기를 따라갑니다.** 꼬리는 다른 데서 드러납니다 —
「한 개가 얼마나 늦을 수 있나」입니다. 균등은 1.50배가 천장인데 로그정규는 2.68배가
나옵니다. 평균이 아니라 **드문 사고**로 나타나는 값이라 안전 재고와 납기에서 갈립니다.

**수리 시간도 흔들립니다.** 예전에는 30분짜리 고장이 언제나 정확히 30분이었습니다 —
실제 수리는 부품이 없거나 원인을 못 찾으면 몇 배가 되고, **그 꼬리가 라인을 세우는
시간의 대부분**입니다. 「수리 시간 편차」를 주면 모양은 위에서 고른 것을 따릅니다.

### 사람 (`core/crew.js`)
설비마다 **필요 인원**을 정하고, **교대조**를 짭니다(8시간 3조 같은 식). 그 조의
총원으로 배치 순서대로 채우고, 모자라면 그 설비는 **무인으로 섭니다.**

> **부분 배정은 없습니다.** 두 명이 필요한 설비에 한 명만 붙이면 그 한 명은
> 아무것도 못 하면서 다른 설비도 못 돌립니다. 채울 수 있으면 통째로 채우고,
> 못 채우면 건너뛰어 **다음 설비가 그 사람을 씁니다.**

교대는 시뮬 시간으로만 돕니다 — 달력·요일·휴일 개념은 없습니다.

### 고장 · 불량 (`core/faults.js`)
- **MTBF** 0~2시간(0 = 고장 없음) · **MTTR** 10초~30분
- **불량률** 0~30% — 불량은 **그것을 만든 설비의** 문제로 셉니다. 남의 OEE 를
  끌어내리지 않습니다

### 지표 · OEE (`core/metrics.js`)
`OEE = 가동률(A) × 성능(P) × 양품률(Q)`

- **A** — 고장과 무인으로 잃은 시간. 애초에 돌 수 없었던 시간입니다
- **P** — 돌 수 있었는데 막힘·굶음으로 못 돈 시간. 잃은 시간으로 보면 둘은 같아서
  P 하나에 넣지만, **막힘은 하류를 늘려 풀고 굶음은 상류를 늘려 풉니다.** 그래서
  숫자 뒤에 어느 쪽인지를 끝까지 따로 들고 갑니다
**리드타임**도 함께 나옵니다 — 한 개가 들어와 나가기까지 몇 분인가.
재공과 처리량은 이미 세고 있었는데 **셋 중 하나가 비어 있었습니다.**

    재공 = 처리량 × 리드타임          (리틀의 법칙)

- **Q** — **그 설비가 만든 것의** 양품률. 전체 OEE 만 개수로 가중한 라인 양품률을
  씁니다 — 둘은 일부러 다릅니다. 같이 쓰면 설비 하나의 불량률을 올렸을 때
  **아무 상관 없는 설비의 OEE 까지 떨어집니다**(실제로 그랬습니다)

### 생산 오더 · 납기 (`core/orders.js`)
「무엇을 몇 개, 언제까지」를 겁니다. 다 채우면 라인이 **스스로 섭니다** — 이때
화면이 통째로 얼어 고장처럼 보이므로, 오더 칸을 두르고 재생 버튼에 링을 둘러
**다시 도는 문**을 짚어 줍니다.

### 라인 능력 — 돌리기 전에 천장을 계산한다 (`core/balance.js`)
돌려 보지 않아도 답이 나오는 질문이 있습니다 — **「그래서 뭘 얼마나 늘려야 하나?」**

능력은 그냥 못 견줍니다. 「제작기 20개/분 vs 조립기 10개/분」을 보고 조립기가
병목이라 하면 **틀립니다** — 조립기가 한 개에 부품 2개를 먹는다면 둘은 균형입니다.
그래서 전부 **「최종 산출물 몇 개/분을 지탱하는가」** 라는 한 단위로 바꿔 세웁니다.

같은 능력끼리는 **묶어서** 보여 줍니다. 하나씩 늘어놓으면 「제작기2 를 고치면 +0.0」
같은 말이 나오는데, 실은 **바로 뒤에 같은 능력의 벨트가 있어서** 둘을 함께 고쳐야
오릅니다.

> **선반·적치대는 여기 안 들어갑니다.** 쌓는 곳은 완충이지 속도가 아닙니다 —
> 적치대가 가득 찼다는 것은 「적치대가 작다」가 아니라 **「그걸 비우는 쪽이 느리다」**
> 는 뜻입니다.

### 물류 동선 (`core/flow.js`)
설비를 옮겨서 달라지는 값은 이것 하나입니다 — **물건이 오가는 거리.**

    운반 작업량 = Σ (시간당 개수 × 그 구간 거리)      [m·개/시]

배치 계획의 고전적인 목적 함수입니다. 무거운 구간이 순서대로 나오니 **무엇을
붙여 놓아야 하는지**가 바로 보입니다 — 「A와 B를 가까이」는 감이 아니라 이 표에서
나오는 말입니다.

> **견주는 잣대는 「한 개가 지나는 거리」입니다.** 총 작업량은 라인이 빨라지기만
> 해도 커져서, 배치를 나쁘게 고쳐 놓고도(느려져서) 숫자가 줄어 보입니다. 개당
> 거리는 그 착시가 없습니다 — 배치가 좋아져야만 내려갑니다.

벨트는 **깔린 길이** 그대로(꺾인 만큼 깁니다), 카트는 **물건이 실려 가는 구간**만
셉니다. 빈 차로 돌아오는 구간은 물건이 안 탔으니까요.

### 여러 번 돌려 보기 (`core/replicate.js`)
아래 띠의 **여러 판** 탭. 고장과 공정 편차가 들어 있으면 **같은 배치도 돌릴 때마다
다른 값**이 나옵니다. 한 번 돌린 숫자 하나로 배치를 견주면 다시 돌렸을 때 뒤집힐
수 있습니다.

    한 번:  412 개/시
    20번:   549 ± 28 개/시 (95%)     ← 견줄 수 있는 값

**화면 없이 돕니다.** 시뮬 틱이 `core/sim.js` 로 나와 있어서 30분짜리 한 판이
몇 ms 입니다 — 20판 × 1시간이 135ms.

**설비만 도는 게 아니라 벨트와 카트까지 돕니다**(`lineFlow`). 만드는 쪽만 돌리면
만든 것이 아무 데도 안 가서 출력 자리가 차고, 밖으로 나간 것이 없어 처리량이
**어떤 도면에서든 0** 이 됩니다. 규칙은 화면과 같은 것을 씁니다 —
`runBelt`·`runCart` 를 그대로 부르고 여기서는 그릇만 만듭니다.

- 씨앗이 고정이라 **같은 도면은 같은 결과**를 냅니다
- 배치 둘을 견줄 때 **같은 난수**를 먹입니다(common random numbers) — 그래야
  「A는 운 좋게 고장이 안 났다」가 아니라 배치 차이만 남습니다
- 판마다 **처음부터** 시작합니다. 앞 판이 남으면 통계가 못 쓰게 됩니다

> **「구간이 겹치나」로 판정하지 않습니다.** 쉽고 그럴듯하지만 지나치게
> 보수적이라 **있는 차이를 없다고 합니다** — 6.0초/개와 5.5초/개(9% 차이)를
> 스무 판씩 돌려 견줬더니 「모른다」가 나왔습니다. 차이 자체의 신뢰구간을
> 봅니다(Welch).

결과에는 **천장의 몇 %인지**가 함께 나옵니다. 「라인 능력」은 고장도 없고 굶지도
않는 라인의 **계산값**이고 여기는 실제로 돌려서 **잰 값**이라, 그 차이가 곧
고장 · 굶음 · 막힘으로 샌 몫입니다.

    처리량  1182 ± 0 개/시
    천장 1200 개/시 의 99% 입니다 — 나머지는 고장 · 굶음 · 막힘으로 샌 것입니다

돌리고 나면 **화면의 이번 실행은 비워집니다** — 여러 판이 같은 자리를 쓰기
때문입니다. 그 사실을 화면이 말해 줍니다.


### 배치 손보기 (`core/optimize.js`)
설비를 **맞바꾸거나 옮겨** 가며 **개당 거리가 줄어드는 조합**을 찾습니다.

    손보면  101.4 m → 69.9 m (−31%)
      1. 제작기 A ↔ 제작기 B      75.0 m
      2. 조립기 → 제작기 A 쪽으로 8.0 m    66.2 m

**도면을 마음대로 바꾸지 않습니다.** 찾은 것을 목록으로 보여 주고 적용은 누르는
사람이 합니다. 눌러도 자리만 맞바꿀 뿐 **방향도 설정도 그대로**이고, 마음에 안
들면 **Ctrl+Z 한 번**으로 통째로 돌아갑니다.

> **처리량은 안 바뀝니다.** 라인의 천장은 공정 시간과 벨트 속도가 정하지 설비가
> 어디 앉아 있는지가 정하지 않습니다 — 줄어드는 것은 **거리**입니다.

맞바꾸기만 하는 데는 이유가 있습니다. 빈 땅으로 흩어 놓으면 값은 좋아지는데
통로가 무너져 **쓸 수 없는 도면**이 나옵니다. 그리고 맞바꾸기는 **말로 옮길 수
있습니다** — 「제작기 1 과 조립기 2 를 맞바꾸세요」는 그대로 실행할 수 있는
지시지만, 「제작기를 (12.75, −4.5) 로」는 그렇지 않습니다.

겹치거나 · 바닥 밖이거나 · 벽·기둥에 걸리거나 · **카트 경로가 깨지는** 자리는
고르지 않습니다. 마지막 것이 특히 중요합니다 — 나르는 양이 0 이면 거리도 0 이라,
막지 않으면 탐색이 **경로를 부수는 쪽으로** 갑니다.

#### 통로와 구역
**카트가 다니는 길 위에는 안 놓습니다.** 맞바꾸기만 할 때는 없어도 됐던 규칙입니다 —
자리가 서로 바뀔 뿐이었으니까요. 빈 자리로 옮기기 시작하면 길 한복판에 설비를
세울 수 있습니다.

> **여유는 두지 않습니다.** 「경로 양옆 1 m 를 비운다」가 자연스러워 보이지만
> 이 도구에서는 틀린 규칙입니다 — 정차역은 경로가 설비 포트 1 m 안을 지나야
> 생기고, 포트는 바운딩 박스 **안쪽**에 있습니다. 여유를 두는 순간 **정상 배치가
> 전부 불법**이 되고 역이 통째로 사라집니다. 지킬 것은 하나입니다 —
> **길 위에 물건을 놓지 마라.**

**구역을 그렸으면 그 안에 머뭅니다.** 지금 어느 구역 안에 온전히 들어 있는 설비만
묶습니다 — 걸쳐 있거나 밖에 있던 것은 원래 자유롭던 것이니 그대로 둡니다.

**어디로 갈지는 이미 알고 있습니다.** 빈 자리를 전부 훑으면 만 자리가 넘어 화면이
멈춥니다. 물류가 무거운 상대 쪽으로만 걸어 보므로 설비당 스물 몇 자리로 끝나고,
나온 답은 **말로 옮길 수 있습니다** — 「조립기 쪽으로 3.5 m」.

#### 오래 걸리면 잘라서 돌립니다
**걸음 수가 아니라 시간으로 끊습니다.** 250ms쯤 찾고 잠깐 쉬었다가 이어서 찾는
식이라, 도면이 커져도 **화면이 안 멈추고** 값이 줄어드는 것이 실시간으로 보입니다.

    설비 21대 · 1124.4 m → 224.5 m (−80%) · 57걸음 · 2.7초

아직 더 줄어드는 중에 멈췄으면 그렇게 말하고 <b>이어서 더 찾기</b>를 내놓습니다 —
「다 줄였다」와 「여기서 끊었다」는 다른 말이니까요.

씨앗도 난수도 없어 같은 도면은 늘 같은 답을 냅니다. 언덕을 내려가다 멈추는
방식이라 **최선이라는 보장은 없습니다.**

### 손잡이 돌리기 — 「얼마가 좋은가」 (`core/sweep.js`)
아래 띠의 **얼마나** 탭. 「카트를 몇 대 두면 되나?」 「버퍼를 얼마로?」 —
값을 손으로 바꾸고 다시 돌리기를 되풀이하는 대신, 도구가 **값을 바꿔 가며**
돌려 보고 표로 냅니다.

    카트 1대   788 ± 68
         2대  1276 ± 310
         3대  1272 ± 311
         4대  1281 ± 311   ← 표에서 제일 큰 값
         8대  1281 ± 315
    → 2대면 충분합니다 — 더 늘려도 안 늡니다

**답은 최고가 아니라 무릎입니다.** 눈으로는 4대가 최고지만 2대와 구간이
겹칩니다 — 「최고는 4대」라고 하면 **필요 없는 트럭을 두 대 더 사게** 됩니다.

돌릴 수 있는 손잡이는 **그 도면에 있는 것만** 나옵니다 — 카트 대수 · 적치대
수용량 · 로트 크기 · 전환 시간 · 벨트 속도 · 교대 정원.

> **값마다 같은 난수를 먹입니다**(common random numbers). 다른 운을 주면
> 곡선이 들쭉날쭉해서 「여기서 꺾인다」가 운인지 실력인지 알 수 없습니다.
> 그리고 판끼리 **짝을 지어** 견주므로 운이 상쇄됩니다.

통계적으로 다른 것과 **할 만한 것**은 다릅니다 — 2% 넘게 늘어야 「늘었다」로
봅니다. 한 값씩 잘라 돌리므로 화면이 안 멈추고 표가 한 줄씩 채워집니다.

### 그래서 얼마 이득인가 (`core/improve.js`)
위 계산은 「고치면 10개/분」까지 말합니다. 그런데 정작 정할 것은 **고칠 값어치가
있는가**이고, 그건 능력만으로도 돈만으로도 안 나옵니다. 설비를 한 대 더 놓으면
**만드는 개수와 나가는 돈이 함께** 커지니까요.

그래서 병목 묶음을 함께 풀었을 때를 **개당 원가 하나로** 보여 줍니다.

```
손보면 얼마 이득인가                        남는 장사
  제작기 1        같은 설비 1대 더
  컨베이어 #1     「한 번에」를 늘리거나 벨트를 빠르게
                       지금        손본 뒤
  천장             3.0 개/분      6.0 개/분
  시간당 비용        1,820원        2,730원
  개당 원가         10.11원         7.58원
  시간당 910원이 더 듭니다. 개당 ▼ 2.53원.
  한 대로는 6.0 개/분까지입니다 — 위에 적힌 10 개/분까지 올리려면 더 놓아야 합니다.
```

**「푼다」가 종류마다 다른 것**이 요점입니다.

| 병목 | 손보는 법 | 드는 돈 |
|---|---|---|
| 설비 | 같은 설비 1대 더 | 전력 + 고정비 + **사람** |
| 벨트 | 「한 번에」를 늘리거나 빠르게 | **0원** |
| 카트 | 대수 n → n+1 | 카트 전력 |

그래서 **벨트가 병목이면 그건 공짜로 고칠 수 있는 병목입니다** — 설비를 사기
전에 여기부터 보라고 말해 줍니다. 설비 쪽에 **사람 몫을 반드시 물리는** 것도
같은 이유입니다. 정원을 안 늘리면 새 설비는 무인으로 서니, 안 물리면 「공짜로
두 배」라는 거짓말이 됩니다.

판정은 **셋**입니다 — 싸지면 `남는 장사`, 비싸지면 `밑지는 장사`, 그리고
**`본전 — 양만 는다`**. 설비를 통째로 두 배 하면 능력도 돈도 두 배라 개당 원가가
정확히 같은데, 그걸 빨갛게 「밑지는 장사」라고 찍으면 거짓말입니다.

> 이 숫자는 **고장도 굶음도 없이 쉬지 않고 도는** 라인의 값이라 늘 실제보다
> 좋게 나옵니다. 그게 곧 위 「천장」의 원가이고, 두 화면이 같은 가정 위에 서
> 있어야 나란히 놓고 견줄 수 있습니다. **돌린 뒤의 진짜 원가는 원가 탭**입니다.

### 원가 · 에너지 (`core/cost.js`)
처리량이 높은 배치가 늘 나은 배치는 아닙니다. **새로 재는 것은 하나도 없습니다** —
이미 세고 있던 돈 시간·선 시간·사람-초·만든 개수에 단가를 곱할 뿐입니다.

| 단가 | 기본값 |
|---|---|
| 전기 | 130 원/kWh |
| 인건비 | 12,000 원/인시 |
| 자재비 | 0 원/개 |
| 설비 전력 | 돌 때 7 kW · **놀 때도 1.2 kW** |

**놀아도 나가는 돈과 놀면 안 나가는 돈**을 갈라 봅니다. 사람은 서 있어도 임금이
나가고, 설비는 놀면 대기 전력만 씁니다 — 그래서 「안 만들면서 나간 돈」이 따로
집계됩니다. 하루·한 주·한 달·한 해로 늘려 보는 칸도 있습니다.

> **너무 짧게 돌리면 경고합니다.** 라인이 다 차기 전, 고장이 한 번도 안 난 구간,
> 교대가 한 바퀴 돌기 전의 숫자는 그 도면의 실력이 아닙니다.

### 보고서 두 장 · 시나리오 비교

| | 어디서 | 무엇이 들어가나 |
|---|---|---|
| **도면 보고서** | 인스펙터 → 도면 요약 | 평면도·설비 목록·라인 능력·**쉬지 않고 돌 때**의 원가 |
| **실행 보고서** | 아래 띠 → 실행 | 처리량·OEE·병목·**실제로 잰** 원가 |

**도면 보고서는 돌리지 않아도 나옵니다.** 도면을 남에게 건넬 때 필요한 것은 대개
그 앞이기 때문입니다 — 「무엇이 몇 대 놓였고, 이 라인의 천장은 얼마인가」.
평면도에는 이름이 아니라 **번호**가 찍히고 아래 설비 목록이 같은 번호를 씁니다
(이름을 얹으면 설비가 조금만 붙어 있어도 글자끼리 겹쳐 둘 다 못 읽습니다).
축척 막대도 함께 들어갑니다.

- **CSV** — 표 계산기로 가져가는 판. 실행 보고서와 같은 값에서 나옵니다
- **시나리오** — 배치를 여러 개 담아 두고 나란히 견줍니다 (`core/scenarios.js`).
  **여러 판으로 저장**하면 처리량에 `± 구간`이 붙고, 아래에 판정이 뜹니다 —
  「A가 B보다 낫습니다 (구간이 0을 안 품습니다)」 또는 「아직 다르다고 못 합니다」.
  한 판으로 담은 배치는 흔들림을 모르므로 판정에 안 들어갑니다.

둘 다 **스스로 서는 HTML** 한 장입니다 — 스크립트도 없고 바깥에서 받아 오는 것도
없어서, 파일만 건네도 그대로 열리고 <kbd>Ctrl</kbd>+<kbd>P</kbd> 로 PDF 가 됩니다.

## 도면 나눠 쓰기

툴바의 **공용 도면** 버튼을 누르면 창이 뜹니다. 저장소에 담긴 예제와, 사람들이
올린 도면이 **썸네일 · 이름 · 설명 · 만든 날짜 · 용량**과 함께 목록으로 나옵니다.
고르면 오른쪽에 속이 펼쳐집니다 — 건물 크기, 설비 종류와 대수, 카트, 오더, 인원,
단가까지 **열어 보지 않고도** 무엇인지 알 수 있습니다.

썸네일은 **화면 캡처가 아니라 도면에서 그린 SVG** 입니다(`core/thumb.js`). 3D 를
띄워 찍으려면 브라우저가 필요한데, 목록은 서버에서도 만들어야 하기 때문입니다.

**불러오면 지금 작업하던 것을 잃습니다.** 그래서 고른 뒤 확인을 한 번 더 받고,
그 자리에서 **먼저 내보내기**를 할 수 있게 해 두었습니다.

올리는 쪽은 툴바의 **공유** 버튼입니다. 이름과 설명을 적어 올리면 **링크**가 나오고,
그 링크로 들어온 사람은 그 도면이 열린 채로 시작합니다. 동시에 위의 **공용 도면**
목록에도 올라갑니다.

> ⚠️ **공유 서버에는 자물쇠가 없습니다.** 주소를 아는 사람은 누구나 올릴 수 있고,
> 올라간 도면은 **링크만 있으면 누구나 엽니다.** 지금은 서로 돌려 보는 용도로
> 그렇게 두었습니다 — 올리는 창이 이 사실을 못 박아 말하고 확인을 한 번 더 받습니다.
> 남에게 보이면 안 되는 도면은 올리지 마세요.

Vercel Blob(icn1 · Public)에 쌓이고, 서버 함수는 `api/share.js` 하나입니다.
환경 변수(`BLOB_READ_WRITE_TOKEN`)가 없는 배포에서는 **공유 기능만 조용히 꺼집니다** —
나머지는 그대로 돕니다.

### 구역 — 사각형을 이어 붙여 ㄱ 자로
**작업영역** 탭의 **구역**으로 사각형을 그린 뒤, **겹치게 한 번 더** 그리면 이어
붙어 ㄱ 자가 됩니다. 펜으로 여덟 점을 찍을 필요가 없습니다.

**아무 구역이나 합쳐지지는 않습니다** — 방금 그려서 **선택되어 있는 구역**에만
붙습니다. 「입고」와 「검사」가 겹쳤다고 하나가 되어 버리면 그린 뜻이 사라지니까요.
딴 구역을 새로 그리려면 <kbd>Esc</kbd> 로 선택을 풀고 그리세요.

구역끼리 **겹치는 것 자체는 막지 않습니다.** 통로와 안전구역처럼 정말 겹쳐야 하는
구역이 있기 때문입니다.

#### 구역이 말해 주는 것 (`core/zoneInfo.js`)
구역은 색칠이 아니라 **가르려고** 그리는 것이라, 그 단위로 따져 줍니다.

| | 뜻 |
|---|---|
| **찬 비율** | 설비가 바닥에 깔린 넓이 ÷ 구역 넓이. 「여기 더 들어가나?」의 답 |
| **인원** | 안에 있는 설비가 요구하는 사람 수 |
| **시간당 비용** | 안에 있는 설비만의 전력 + 인건비 |
| **지나는 카트** | 몇 경로가 · 몇 m 나 이 구역을 통과하나 |

> **찬 비율은 통로를 뺀 값이 아닙니다.** 90%라고 못 다니는 것도, 40%라고 넉넉한
> 것도 아닙니다 — 통로는 사람이 보고 정할 몫이라 그 판단을 숫자가 대신하지
> 않습니다. 그래서 좋고 나쁨을 색으로 말하지 않고 눈금만 그립니다.

비용은 원가 화면과 **같은 함수**를 씁니다. 다만 카트 전력은 뺐습니다 — 경로가
여러 구역에 걸쳐 있어 어느 구역 몫인지 가를 수 없기 때문입니다.

### 화면 테마
툴바 오른쪽의 해/달 버튼으로 **라이트 · 다크**를 바꿉니다. 3D 배경·바닥·그리드와
조명까지 함께 바뀌고, 선택은 브라우저에 기억됩니다. 처음 실행할 때는 OS 설정을
따릅니다.

**설비를 옮기면 연결도 알아서 다시 늘어나고 다시 꺾입니다.**
연결은 끝점 두 개만 저장하고 경로는 매번 다시 계산하기 때문입니다.

### 층 — 레일이 겹칠 때 쌓기
이미 깔린 레일과 평면상 겹치는 자리에 새 레일을 그리면 **자동으로 위층에 놓입니다.**
0층부터 올라가며 비어 있는 첫 층을 찾고, 그리는 중에도 미리보기 라벨에 `· 1층` 처럼
표시됩니다. 층 간격은 1.0m 이고, 양 끝은 포트 높이를 그대로 지키면서 가운데 구간만
완만하게 들립니다(경사 3m).

레일을 클릭해 선택하면 인스펙터에서 **올리기 / 내리기**로 층을 직접 바꿀 수 있습니다.
어느 레일이 위로 갈지는 결국 사람이 정하는 것이라, 자동 배정은 시작값일 뿐입니다.
지지 다리는 그리지 않습니다(가시화용 모델 기준).

### 벨트
- **폭** — 인스펙터에서 0.3~3m 로 조절합니다. 중심선 기준으로 좌우가 벌어지고
  길이·높이는 그대로입니다. 연결마다 따로 지정됩니다.
- **구동** — 툴바의 ▶/⏸ 로 전체를 켜고 끄며, 옆 슬라이더가 전역 기본 속도입니다.
  연결별로 다른 속도를 주고 싶으면 인스펙터에서 지정하면 되고, "전역 기본값으로
  되돌리기"로 되돌릴 수 있습니다.
  벨트 표면 UV 를 흘려서 표현하며, **윗면과 아랫면이 서로 반대로** 흐릅니다.

### 치수 재기 (자)
툴바의 **자** 아이콘을 누르고 바닥을 **두 번 클릭**하면 그 사이가 몇 m 인지 나옵니다.
셋째 클릭은 새로 재고, <kbd>Esc</kbd> 로 지웁니다.

```
3.61 m · 가로 3.00 · 세로 2.00
```

거리 하나만 보여 주면 비스듬한 두 점에서 쓸모가 적습니다 — 실제로 알고 싶은 것은
대개 **축에 붙은 치수**라서, 「통로 폭이 3m 인가」에 답하려면 가로·세로가 따로
있어야 합니다.

- 다른 도구와 **같은 커서**를 씁니다 — 스냅을 켜 두었으면 잰 값도 그리드에 떨어집니다
- **탑뷰로 돌아갑니다.** 비스듬히 보면서 잰 거리는 못 믿습니다
- **도면에 남지 않습니다.** 자를 대 보는 것은 그리는 동안의 손놀림이지 결과가
  아니므로 저장도 내보내기도 되지 않습니다. 남기고 싶은 치수는 구역을 그리거나
  벽을 세워서 남기세요

크기·포트·1 피치 길이를 보여 줍니다. 분류(설비/연결장치)와 연장 방식
(모델 반복 / 튜브)을 고르고 추가하면 라이브러리에 들어갑니다.

- GLB 원본은 **IndexedDB**, 배치와 라이브러리 메타는 **localStorage** 에 저장됩니다.
- 배치는 0.6초마다 자동 저장되고, 툴바에서 JSON 내보내기/불러오기도 됩니다.

> **모델을 만들 때 유입/유출부를 어떻게 넣어야 하는지**는
> **[docs/MODELING_GUIDE.md](docs/MODELING_GUIDE.md)** 를 보세요.
> 포트가 없는 모델도 배치되지만, 에디터가 바운딩 박스로 추정한 임시 포트를 씁니다.
>
> 무엇을 왜 그렇게 정했는지, 어떤 함정을 밟았는지는
> **[docs/HANDOFF.md](docs/HANDOFF.md)** 에 있습니다 — **이것이 가장 최신 기록**입니다.
> [docs/DEVLOG.md](docs/DEVLOG.md) 는 초기 7회차에서 멈춰 있습니다.

판정을 만들어 놓고 컴포넌트에 안 이어 주는 실수는 값 검사로 안 잡히기 때문입니다.
`guides.mjs` 는 한 걸음 더 나가서 **따라 하기가 부르는 칸 이름이 화면에 실재하는지**
대조합니다(안내와 화면이 어긋나는 사고는 그것 말고는 아무 데서도 안 터집니다).

**GLB 도 Node 에서 읽습니다.** `globalThis.self = globalThis` 한 줄이면 three 의
GLTFLoader 가 그냥 돕니다 — 텍스처만 못 읽고 노드 이름 · 좌표 · 바운딩 박스는
전부 나옵니다. 그래서 검사가 **실제 모델 치수로** 도면을 세워, 제작기 → 컨베이어
→ 적치대 → 트럭 → 개구부까지 **끝에서 끝까지** 돌려 봅니다(`lineflow.mjs`).

여기서 **안 잡히는 것**은 그림 그 자체입니다 — 렌더링과 픽킹.

### 좌표·수치 규칙
- 단위는 **미터**, 바닥 평면은 XZ, 높이는 Y.
- 회전은 라디안이 아니라 **0..3 정수(×90°)** 로 저장합니다.
  부동소수 오차가 누적되지 않고, 회전된 풋프린트를 정수 연산으로 얻습니다.
- 저장되는 좌표는 전부 **스냅이 끝난 확정값**입니다. 마우스 좌표는 씬 안에서만
  존재하고, 상태로 들어오는 순간 그리드에 정렬됩니다.
- 도면 크기는 120 × 120 m (`FLOOR_SIZE`).
